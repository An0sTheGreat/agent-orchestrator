# Local API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An OpenAI-compatible API on `http://127.0.0.1:8830/v1` with a bearer key, so another app on this PC can run chat completions on AO's workers and generate pictures with AO's local image models.

**Architecture:** A new `HttpListener` server (`LocalApi.cs`, pure parts + listener; `MainWindow.LocalApi.cs`, routes needing the window). Chat is a pass-through: the engine's new `--api-target` readies the worker and prints where it is served; C# forwards the app's body (worker sampling underneath) with `HttpClient` and pipes the reply back unchanged. Images reuse `GenerateForShareAsync`'s path.

**Tech Stack:** .NET 8 WPF (C#), Python 3 engine (`orchestrator.py`, unittest in `test_orchestrator.py`).

**Spec:** `docs/superpowers/specs/2026-11-26-local-api-design.md`

## Global Constraints

- Listen on `http://127.0.0.1:<port>/` only; refuse a non-loopback remote (403) and a `Host` other than `127.0.0.1:<port>` / `localhost:<port>` (403).
- `Authorization: Bearer <key>` compared with `CryptographicOperations.FixedTimeEquals` over UTF-8 bytes; the body is not read before the key passes; 401 in the OpenAI error shape `{"error":{"message":"…","type":"invalid_request_error"}}`.
- Default port **8830** (`AppSettings.LocalApiPort`, settings.json only); `AppSettings.LocalApi` off by default.
- Key: `ModelShare.NewKey()`, saved with `ApiKeys` under `AO_LOCAL_API_KEY`, **never** exported by `ApiKeys.ApplyAll`.
- No provider key value ever appears in a reply, an error or a log; `--api-target` prints the variable **name** only.
- No dialog, no change to `_settings` beyond `LocalApi`/`LocalApiPort`, no conversation saved, no picture written to the gallery.
- Body limit 25 MB. No CORS headers.
- Don't touch the voice files (Speech.cs, Tts.cs, Chatterbox.cs, MainWindow.Voice/SpeakOut/Dictation/WebVoice*), the repo-root `App.xaml.cs` or `requests.txt`.
- Commit messages via `git commit -F <file>`, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; commit to master.
- Tests run hidden from the Debug exe: `Start-Process <Debug exe> --self-test|--webapp-smoke -WindowStyle Hidden -PassThru -Wait`, exit code 0 = pass.

## Review Focus

1. A request with `Authorization: Bearer <key>x` or a key of a different length → 401, no timing shortcut (Task 2 test).
2. The app hangs up mid-stream → the upstream request is cancelled and the semaphore/`ChatModelsInUse` flag is released (Task 4 smoke: second call after a dropped one still works).
3. An upstream 401 whose body echoes the provider key → relayed with `***` (Task 2 `Scrub` test, Task 4 smoke).
4. `model` given by a custom worker's title in other case (`"my coder"`) → resolves to its id (Task 2 test).
5. AO busy and the worker's model not loaded → 503 with `Retry-After: 10`, nothing loaded or stopped (Task 1 test for the engine, Task 4 smoke for the route).
