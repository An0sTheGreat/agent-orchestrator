# Agent Setup

Agent Setup is a local Windows launcher and bounded three-model software-development orchestrator for local llama.cpp models. It sequences a Planner, Implementer, and Reviewer while keeping each implementation task small, project-scoped, and independently reviewed.

## Quick start

1. Launch `dist\Agent Orchestrator.exe` and download llama-server under **Options**.
2. Select or type the target project folder.
3. If prompted, initialize the project. A nonexistent target folder will be created.
4. Edit the target project's `PROJECT.md` with its goal, constraints, phases, and completion criteria.
5. Leave **Run one reviewed task, then stop** enabled for the safest default behavior.
6. Click **Start workflow**.

The launcher is self-contained for .NET, but Python 3.11 or newer must be installed and available on `PATH`.

## Project initialization

Initialization creates or completes the target folder without overwriting existing files. Every initialized project receives:

- `PROJECT.md` — user-owned authoritative goal, phases, constraints, and completion criteria.
- `STATE.md` — reviewer-approved progress only.
- `TASK.md` — current bounded task selected by the Planner.
- `RESULT.md` — latest Implementer result.
- `REVIEW.md` — latest Reviewer verdict and evidence.
- `ISSUES.md` — known blockers and exhausted review failures.
- `config.json` — project-local limits, model settings, and approved validation commands.

During initialization, **Use custom PROJECT.md…** and **Use custom config.json…** can select user-supplied source files. Selected files are copied under the standard names only when the destination file is missing. Existing destination files are preserved and the launcher reports when a selected custom file was skipped.

## Workflow

The normal loop is:

`configure project -> plan one task -> implement within allowed files -> review -> repair if needed -> record verified state -> plan again`

The Planner may allow only one to three project-relative files per task. The Implementer can read or edit only those files and can run only named commands from `validation_commands`. The Reviewer is read-only and independently judges the task, diff, and available validation evidence.

`STATE.md` advances only after a Reviewer `PASS`. A failed review receives bounded repair attempts. Malformed JSON, invalid Planner task contracts, and invalid Reviewer verdicts also receive bounded correction attempts before the workflow stops.

## Project-local configuration

On the first run, the Planner reads `PROJECT.md`, a bounded project inventory, and recognized build manifests. It proposes only `validation_commands`; model endpoints and loading settings are inherited from the Agent Setup template and are not generated by the model.

If no validation command is justified yet, an empty command set is valid. The configurator checks again after project files change. To force regeneration later, set `project_configured` to `false` in the target project's `config.json`.

Validation commands are argument arrays executed directly with `shell=False`. Shells and inline-code flags are rejected, but this is not a complete security sandbox. Review generated commands and use source control or a disposable copy for valuable projects.

## Models and limits

The supplied template runs each role's model on llama.cpp's llama-server, one at a time:

- Planner: Qwen3.5 4B
- Implementer: Qwen2.5 Coder 3B
- Reviewer: Phi-4 mini

Default bounds are 20 tasks, two review-repair rounds, and 30 tool steps per agent turn. Only one role occupies the GPU at a time.

## Launcher controls

- **Browse…** selects an existing target folder; a new path may also be typed.
- **Initialize Project** creates the target if necessary and adds missing workflow files.
- **Run one reviewed task, then stop** maps to `--once`.
- **Edit PROJECT.md** opens the selected project's specification.
- **Copy full log** copies the entire output buffer, including scrolled-off lines.
- **Stop** terminates the Python process tree for the active run.

## Command-line use

From the Agent Setup root:

```powershell
python .\orchestrator.py --project 'Y:\path\to\initialized-project' --once
```

Set `AGENT_ORCHESTRATOR_LLAMA_SERVER` to the full path of `llama-server.exe` for direct command-line use.

## Source layout

- `orchestrator.py` — orchestration loop, API client, tools, validation boundaries, and recovery logic.
- `config.json` — initialization template and local model configuration.
- `prompts\` — Planner, Implementer, Reviewer, and Configurator system prompts.
- `launcher\AgentOrchestrator\` — WPF launcher source.
- `dist\Agent Orchestrator.exe` — published self-contained Windows launcher.
- `test_orchestrator.py` — Python unit tests for parsing, safety, configuration, and correction behavior.
- Root workflow Markdown files — templates copied into initialized projects.

## Build and verification

Python tests:

```powershell
python -m unittest -v
python -m py_compile orchestrator.py
```

Launcher build and self-test:

```powershell
dotnet build .\launcher\AgentOrchestrator\AgentOrchestrator.csproj -c Release -r win-x64 --self-contained true --no-restore
$p = Start-Process '.\launcher\AgentOrchestrator\bin\Release\net8.0-windows\win-x64\Agent Orchestrator.exe' -ArgumentList '--self-test' -WindowStyle Hidden -Wait -PassThru
$p.ExitCode
```

Publish the single-file launcher to `dist\` (close the app first), then commit and push `dist\Agent Orchestrator.exe`; it is stored with Git LFS, so other machines get it with `git pull`:

```powershell
.\publish.ps1
```

## Operational cautions

- Do not expose environment variables or copied credentials in logs or handoffs.
- Do not edit project workflow records while a run is active.
- The EXE may move only with access to the Agent Setup tree containing `orchestrator.py`, `config.json`, and `prompts\`.
- Generated application code can still be harmful even when file and command scope is bounded.
- Treat model output as untrusted until deterministic validation and Reviewer evidence support it.
